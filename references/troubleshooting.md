# 按失败层级排查

| 现象 | 首先核对 | 修复方向 |
| --- | --- | --- |
| 模型说没有画图工具 | MCP tools/list 与真实 DSH schema 是否都包含生成工具 | 重连 GUI 实际后台的 MCP；检查 profile/preset 过滤与工具缓存 |
| 改了 MCP 还是看不到 | 是否重启了另一份 Web 后台 | 由 GUI 父子进程和监听端口确认实际后台，保留原会话后再重载 |
| 十几秒报错，桌面还在画 | MCP HTTP 的默认超时是否仍是 15 秒 | 内外层统一时间预算；不能把“请求超时”直接当成“没有生成” |
| 找不到固定聊天 | 主页面是否选成了浮窗，侧栏是否还没加载、折叠或虚拟滚动隐藏 | 选唯一主页面，等待侧栏，手动让目标聊天可见；不要自动新建 |
| 页面有聊天却匹配不到 | 节点是否为 DIV role=button；标题、aria-label、全角分隔符是否一致 | 使用观测到的节点语义和精确名称，别只查 button/a |
| 重名时无法绑定 | 有几个可见节点具有相同标题 | 手动改成唯一名称；本例不通过内部 UUID 路由强行导航 |
| 返回上一次生成图或三视图 | 是否仍在使用 v1.0.0 的整页图片基线逻辑 | 更新为 v1.0.1 的请求标记 → 对应消息块 → 完成状态 → 唯一生成图，不只更新一个文件 |
| 长聊天加载历史时误取图 | 历史图片异步加载是否产生新的 src/DOM | 新节点/新 blob 不等于本轮出图；新版只接受当前请求消息中的生成图，并在取字节前再次核对消息 ID 和 src |
| 新版找不到本轮消息或拒绝取图 | 唯一请求标记是否出现在用户消息、消息块状态/生成图节点属性是否改变 | 观察当前页面的 data-talvt-turn-state、generated-image-preview、data-chatgpt-search-message-ids；适配后回归验证，不能回退为整页最后一张图 |
| 两个请求的图片串了 | 是否并发操作同一个固定 Chat | 使用跨进程锁，忙时拒绝；要队列就明确实现单一串行队列 |
| 私聊能用、群聊不回 | 最近群消息是否有真实 @；目标群在不在白名单 | 正常未 @ 就不请求模型；有 @ 则继续查 DSH 和工具日志，不随便放宽触发条件 |
| 群里模型确实调用工具却没图 | 工具结果、固定聊天定位和 QQ 上传返回值 | 不把一切归咎群权限；每层看实际错误 |
| 工具成功却出现多余总结/重复图 | 生成工具是否归类为发送工具；提示词是否又要求 send-image | 成功后视作已发图，禁止第二次发送同图 |
| PNG 有了但 QQ 没收到 | send_group_msg/send_private_msg 的 retcode 和 get_msg | 检查实际目标、授权、上传格式；不能只看本地文件 |
| 普通文字聊天报 tool input is invalid JSON | DSH 是否在执行工具前就解析失败 | 这是工具参数解析层错误。仅当确认没有任何工具调用、原真实 @ 仍有效时，可对原请求重试一次 |

## 参数 JSON 错误的一次重试

可作为桥接增强，**不属于生图主链的必需步骤**：

- 精确识别错误 `DeepSeek Messages stream: tool input is invalid JSON`。
- 仅原真实 @ 发起、没有暂停、不是后台静默回合、尚未调用任何工具时考虑重试。
- 同一个 @ 只一次；新普通消息不得补充重试预算，新真实 @ 才重新允许。
- 保留原会话上下文和已展示消息水位；不要重新创建角色会话。
- 已有任意工具调用（哪怕返回未知）不自动重试，避免重复图、重复发言或其他副作用。
- 第二次仍失败则记录错误并停止，不掩盖持续故障。

这只是容错，不能修复模型本身，也不代表以后不会输出无效 JSON。

## 版本兼容和长期使用

示例针对中文界面及实测 Electron DOM。英文界面、编辑器变更、旧图片虚拟化、登录失效、额度用完、风控/验证码、客户端更新都会影响结果。出现登录/额度限制应让用户在官方界面处理，不自动绕过。

复用固定聊天会累积历史，但不等于每轮把全部图片字节都发给 DSH；两个产品的上下文是分开的。角色一致性也不是保证，必要时在原 Chat 补传标准图。不要承诺无限上下文、无限生图或无需登录。
